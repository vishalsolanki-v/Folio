# Decisions and deviations from plan.md

One line each: what, why.

- M0: AGP 9 built-in Kotlin is used (no `org.jetbrains.kotlin.android` plugin applied; it is declared `apply false` in the root only to pin the Kotlin version), because AGP 9 rejects applying it by default.
- M0: compileSdk/targetSdk 37 (latest stable platform in the SDK on 2026-10-27).
- M0: Toolchain lives on D: (`D:\Android\{Studio,Sdk,.gradle,.android}`, Studio config in `D:\Android\StudioData`); JDK = Android Studio's bundled JBR.
- M1: pdfiumandroid pinned to 2.0.3 (last stable; 3.x is alpha). Its arm64/x86_64 `.so` files are 16 KB aligned (32-bit ones aren't, which Play doesn't require); verified with zipalign -P 16 and ELF headers, and the PDF test passes on the 16 KB-page API 37 emulator. No PdfRenderer fallback needed.
- M1: mammoth failed on Android (Android's SAX factory rejects `disallow-doctype-decl`; Android also ignores the `javax.xml.parsers.SAXParserFactory` system property, so a factory shim can't work). Fix: a modified copy of mammoth's 60-line `SimpleSax` in `app/src/main/java/org/zwobble/...` that rejects any DOCTYPE via a LexicalHandler, plus a Gradle artifact transform (`StripMammothSimpleSax` in app/build.gradle.kts) that removes the original class from the mammoth jar. When upgrading mammoth, diff upstream SimpleSax.java against our copy. The in-house DOCX walker fallback is no longer needed for M10, and M10's "<!DOCTYPE" pre-scan is unnecessary (covered by test `mammoth_doesNotResolveExternalEntities`).
- M1: Espresso pinned to 3.7.0 for androidTest; the 3.5.0 pulled in by compose-ui-test crashes on API 37 (`InputManager.getInstance` removed).
- M1: Release APK permissions: only `WAKE_LOCK` (from Media3, normal permission, no prompt) and androidx's internal receiver permission. No network or storage permissions.
- M2: Fonts are the variable Inter (opsz + wght) and JetBrains Mono (wght) from google/fonts, bundled in res/font (~1 MB). Inter is used at optical size 14 for text and 32 for headlines (`InterText` / `InterDisplay`). OFL license texts are in assets/licenses for the M5 licenses screen.
- M2: 38 Material Symbols (weight 300) converted from SVG to vector drawables by a small script; push_pin only exists in the older 24-unit format, so it uses a 24 viewport.
- M2: The design catalog is a debug-only launcher activity (`src/debug`, "Folio catalog"; `adb shell am start -n com.folio.app/.debug.DesignCatalogActivity --es theme Dark`). M5 should also link it from Settings in debug builds.
- M2: FindBar has `autoFocus` (default true) so the viewer focuses it immediately; the catalog turns it off.
- M3: `TextCodec` does not normalise line endings (plan §4.5 said normalise to `\n`). Text keeps its original separators, so an unedited decode→encode is byte-identical even for mixed endings; `lineSeparator` is just the default for new lines. M7 must confirm Sora keeps per-line separators (if not, normalise only when the file has a single separator style). `TextDoc` has no `endsWithNewline` (the text itself carries it).
- M3: `MimeSniffer.detect` owns the whole priority order (magic > ZIP peek > extension > intent MIME > text heuristic); `FileResolver` just calls it. A truncated or unreadable ZIP falls back to a ZIP-based extension (docx, xlsx...) when present. Generic MIME types (text/plain, octet-stream) never override a known extension.
- M3: `FileSaver` keeps new content in memory (editing is capped at 5 MB) instead of a `.new` file. It refuses to overwrite when the original is over 50 MB (it can't back it up), and keeps the `.bak` if restoring fails, so the original is never lost. Tested with failing fakes and on a real FileProvider with mode "wt".
- M3: `ZipSafety.Budget` is `startEntry(compressedSize)` + `written(chunk)` so it can stop a bomb mid-write.
- M3: vcf and ics map to the TEXT family (readable as text) until their v1.1 viewers; other v1.1 formats map to UNKNOWN with proper names and badges.
- M3: `UriAccess.canWrite` reads `Document.COLUMN_FLAGS` directly instead of adding androidx.documentfile.
- M3: The mammoth transform is not requested on unit-test classpaths (it dropped the app's own classes there); JVM tests don't need it.
- M4: Recents/folders logic lives in `core/data/Library.kt` (one class, because the persisted-grant budget spans recents and folders). It trims to 500 rows (pinned never trimmed), keeps grants under 100 (API < 30) / 450, releases grants and deletes private copies of dropped rows, and evicts copies (pinned kept) after each change. Permission release is injected so the rules are tested on-device with an in-memory Room DB.
- M4: Room schema is exported to `app/schemas` (version 1) so future migrations can be tested.
- M4: Settings read falls back to defaults on a corrupt preferences file and clamps editor font size to 12–20 sp; unknown stored enum names fall back to defaults.
- M5: Home's "Open file" button is a shadowed PillButton, not ExtendedFloatingActionButton: the M3 FAB's label reached accessibility services empty (uiautomator showed text=""), so TalkBack would say only "button".
- M5: Text fields (Home search, viewer find bar) carry their placeholder as contentDescription; the visual placeholder alone wasn't announced.
- M5: Swipe-to-remove uses a plain `remember`ed SwipeToDismissBoxState, not the saveable `rememberSwipeToDismissBoxState()`: LazyColumn restored the "dismissed" state when Undo brought a row back, which removed it again at once. Covered by `HomeRemoveUndoTest`.
- M5: The Undo snackbar uses SnackbarDuration.Long (10 s). M3 defaults to Indefinite when there is an action. If Home leaves composition while it shows, the removal is committed.
- M5: Snackbars sit above the keyboard (`imePadding`), so Undo is reachable while searching.
- M5: The viewer is still a placeholder screen, but `ViewerViewModel` is real: it resolves the file, falls back to the private copy when the original is gone (recorded under the original URI), takes a copy for temporary URIs (not for picker-persisted or added-folder URIs), and records the open in Recents.
- M5: Folder browsing uses `DocumentTree` (one ContentResolver query per folder); files opened from an added folder are not copied or individually persisted, since the folder's grant covers them.
- M5: Licenses screen lists bundled non-Maven assets (fonts, icons, modified mammoth class, Sora's LGPL notice) above AboutLibraries' generated list; `res/raw/keep.xml` keeps that data from AGP 9 resource shrinking.
- M5: Manual-test samples are generated by a script into `D:\code\Document App\sample-files` (outside the repo). adb-pushed files need a media scan (`adb shell content call --uri content://media --method scan_volume --arg external_primary`) before the system picker's Downloads view lists them.
- M6: When a file arrives through the system "Open with" sheet, `Activity.referrer` is null (seen on API 37). The source label then comes from the URI's authority (`com.whatsapp.provider.media` → WhatsApp, Downloads/Media/External storage providers → Files); `SourceApps.label` accepts a package or an authority (exact or package prefix). Opens from inside Folio pass no source.
- M6: Recents dedupe: one file can reach Folio under several URIs (the Downloads provider has more than one form), so `Library.recordOpen` replaces older rows with the same name + size + MIME (releasing their grant/copy, keeping a pin). Known limit: two distinct files with identical name and size share one row.
- M6: Viewer route carries `source`, `record` (false for shared text and, later, archive entries) and `asText` ("Open as text"). "Open as text" is only offered once a TEXT viewer is registered, so M6 never shows it.
- M6: Shared text without a file is written to `cacheDir/shared_text/<sha1(text)>/<subject>.txt` (stable across rotation) and not recorded in Recents.
- M6: Format content gets shell actions (Open with another app, File info, Open as text) through `LocalViewerActions`; `ViewerError` is the shared "can't show this" screen.
- M6: The Unknown viewer keeps the hex peek behind "Show raw bytes" to keep the screen calm.
- M6: Each external open is its own `ExternalOpenActivity` (standard launch mode) running the shared nav graph from Viewer or SharedFiles; Back past the start screen finishes it. Verified on the emulator: Files app → Open with → Folio → Back returns to Files (same task); Share of 1 and 3 files.
- M7: `UriAccess.canWrite` now relies on the write grant only. The Media documents provider grants read+write (mode=0x3 persisted) but doesn't set `FLAG_SUPPORTS_WRITE`, so files picked in Folio were wrongly "Save copy only". `FileSaver` backs up, verifies and restores, so a provider that can't really write ends in the Save copy fallback instead of damage.
- M7: Sora setup order matters: the TextMate colour scheme must be set before `setEditorLanguage` (else no highlighting), and Folio's colour overrides must be applied after the scheme is attached (attaching re-applies the theme). Both found on the emulator.
- M7: Grammars come from VS Code's built-in extensions plus fwcd/vscode-kotlin (MIT). Licenses per cgmanifest: MIT, BSD (Dart), Apache-2.0 (Dockerfile) and the TextMate Bundle License (ini, html, diff, lua, parts of c/js/markdown), which only says "permission to copy, use, modify, sell and distribute is granted" — accepted as permissive though plan §1 listed only MIT/Apache/BSD. TOML/properties/env use the INI grammar. Two muted Folio themes (light/dark) in assets/textmate.
- M7: Text printing uses `PrintedPdfDocument` + `StaticLayout` on background threads (no WebView, so it doesn't wait for M10's SafeWebView); it prints the first 2 MB.
- M7: Viewer-specific More-sheet options use `FormatViewer.toggles()` + `ViewerState.toggles` ("Pretty view" for JSON/XML). XML pretty view drops the DOCTYPE. `ViewerState.editBlockedReason` hides the Edit pill and shows the disabled "Editing not available" row (too big / unusual encoding).
- M7: Markdown Preview renders in a scrolling Column (not lazy; files are capped at 5 MB). Local images aren't shown; links use Compose's default handler (they open in the browser).
- M7: Editor Preview toggle exists for Markdown only; HTML preview comes with M10's SafeWebView. The editor stays composed under the preview so nothing typed is lost.
- M7: Drafts: `filesDir/drafts/<sha1(uri)>.txt`, written every 5 s while dirty and on ON_STOP, atomically (temp + rename), deleted on save/discard, moved with "Save copy". Verified: force-stop mid-edit → reopen → "You have unsaved changes from earlier" → Restore.
- M7: The viewer reloads after an editor save through a `reload` key on its back-stack entry's SavedStateHandle.
- M7: Read-only viewers keep Sora's selection handles so text can still be selected and copied.
- M7: Compose UI tests use the v2 rules (`androidx.compose.ui.test.junit4.v2`); the deprecated v1 rule's unconfined dispatcher made the Markdown test crash in Compose's SlotTable during disposal on API 37. The real app didn't crash in 5 open/leave cycles.
- M7: Verified byte-exact saves on the emulator: UTF-8 LF (+1 char) and UTF-16LE+BOM+CRLF with non-ASCII (+1 char) differ from the originals only by the typed character; Save copy writes a new file and leaves the original untouched.
- Dev note: when scripting edits with Python on Windows, use `python -X utf8` (cp1252 default breaks on non-ASCII sources).
- M8: One Coil ImageLoader lives in `AppContainer` (AnimatedImageDecoder on API 28+, GifDecoder below, SvgDecoder; no network module). Images show in telephoto's `ZoomableAsyncImage`, which tiles big images: an 8000×6000 JPEG zoomed to pixel level used ~100 MB PSS for the whole app, no OOM.
- M8: Images have no Paper option (`supportsPaper = false`); they sit on a neutral backdrop that follows the app theme. HEIC needs API 28 and AVIF API 31; older phones get a clear message. Image print = one page fitted in the margins via `PrintedPdfDocument` (decoded to at most ~2400 px); SVG has no Print row.
- M8: Media uses ExoPlayer with audio focus, "becoming noisy" pause, pause on ON_STOP, release on dispose, and position/play state kept across rotation. Video uses Media3's `PlayerView`; its controller visibility drives Folio's immersive mode. Any playback error leaves immersive mode so the error screen keeps its top bar.
- M8: The API 37 emulator's hardware H.264 decoder (`c2.goldfish.h264.decoder`) fails mid-stream on every MP4 tried (High and Baseline profile). `DefaultRenderersFactory.setEnableDecoderFallback(true)` is on (covers decoders that fail to initialise) but doesn't rescue that. The same High-profile clip plays on the API 26 emulator, including rotation, so video playback is verified there; re-check on a real Android 15+ phone before release.
- M8: Media samples are generated with ffmpeg into sample-files/media (48 MP JPEG, animated GIF, H.264 MP4 with AAC, MP3 with cover art and ID3 tags, SVG, WebP).
- M9: `PdfDocumentHandle` is the only class touching PDFium. It uses the library's blocking API on one shared `Dispatchers.IO.limitedParallelism(1)` instead of the library's suspend wrappers, so renders, search and close never overlap and queued renders for pages scrolled away are cancelled before they start. Providers without a real file descriptor (statSize -1) are copied to `cacheDir/open/` first.
- M9: Zoom is Folio's own pinch/double-tap code (a `graphicsLayer` scale on the whole page column plus side panning), not telephoto's `Modifier.zoomable`: wrapping a LazyColumn in telephoto fights the list for one-finger drags. Pinch is read in the Initial pointer pass and only multi-touch is consumed, so normal scrolling stays with the list. Max zoom 4×.
- M9: After a zoom settles (250 ms), visible pages re-render at width × zoom in 256 px steps, capped at 4096 px and 8 MP per page (~32 MB) so memory stays under the ~250 MB target; above ~2.2× on an A4 page the render is slightly soft. Measured on API 37: 174–219 MB PSS while flinging through 200 pages; API 26: 145 MB. LRU bitmap cache = 1/8 of max heap (plan said 1/6; 1/6 hit ~245 MB).
- M9: Search highlights use PDFium text rects mapped through `mapRectToDevice` (handles rotation and crop boxes), stored as page fractions; every hit on a page is tinted, the current one stronger. Verified exact on the 200-page sample.
- M9: The password prompt is drawn inside the PDF content area (lock icon, field, Open), not a bottom sheet, so `formats/pdf` doesn't depend on `feature/viewer`. Passwords are kept in a process-memory map only (never saved state), so rotation doesn't ask again. Encrypted PDFs still show Print; the system print service may then fail to read them.
- M9: Paper themes on PDFs are a per-channel colour matrix that maps white paper/black ink to the paper's own background/ink (so Dark also inverts images, like other readers' night modes). Print hands the original bytes to the print system.
- M9: PDF samples (sample-files/pdf: 200 pages with a landscape page 120 and "invoice" on pages 3 and 150, RC4 password PDF, truncated PDF) are generated with reportlab + pypdf in `D:\Android\pyenv`. adb can't send a reliable double tap on the API 37 emulator (two `input` calls arrive as two single taps), so double-tap zoom was checked by eye only.
- M10: `SafeWeb` (core/viewer) is the only WebView setup: JavaScript off, network loads and network images blocked, file and content access off, Safe Browsing off, links/forms/meta-refresh blocked in `shouldOverrideUrlLoading`, and `shouldInterceptRequest` answers every sub-resource with an empty response except `data:` URIs and the bundled font. The manifest opts out of WebView usage metrics. Verified with a hostile test page: no script output, no external or local-file images, empty iframe, links and a 3 s meta refresh do nothing.
- M10: Inter reaches WebView pages via the base URL `file:///android_res/font/` (`url(inter.ttf)`), which works with file access off (checked on API 26 and 37). Re-check in the R8 release build (M14); fallback is a base64 `data:` font.
- M10: Find in Word/HTML uses WebView's own `findAllAsync`/`findNext`, so highlights use Chromium's yellow/orange, not Folio's accent (no JavaScript to restyle them).
- M10: DOCX: mammoth with a style map that also turns Word's Title/Subtitle into headings; output wrapped by `HtmlTemplates.wrap` (Inter, 760 px column, hairline tables that scroll sideways, paper colours as CSS variables). A "Simplified layout" note opens a short explanation sheet. Damaged DOCX → the standard damaged-file screen.
- M10: `HtmlViewer` lives in `formats/text` (not `formats/html`) because its Source mode and editing share the text loader and viewer; formats must not depend on each other. HTML files get scripts stripped (regex, defence in depth) and paper colours injected as low-priority defaults, so pages with their own colours keep them. The editor's Preview now covers HTML too, through the SafeWebView.
- M10: Printing Word/HTML uses `WebViewPrintAdapter`: an off-screen SafeWebView loads the page on the first layout pass, then WebView's print adapter takes over (always Light paper).
- M10: Samples in sample-files/docs (report.docx with title, headings, lists, table, image; truncated damaged.docx; hostile page.html) are made by a python-docx script; python-docx is installed in `D:\Android\pyenv`.
- M11: `XlsxReader` uses `java.util.zip.ZipFile` (random access), so XLSX from content URIs is first copied to `cacheDir/open/<sha1>.xlsx` (local copies are read in place). Sheets load lazily per tab and stream; workbook/styles/shared-strings parts are capped at 50 MB and a sheet part at 512 MB of XML (zip-bomb guard), plus the plan's 100,000-row / 1,000-column caps.
- M11: Number display: 15 significant digits (Excel's precision, so 0.1+0.2 shows 0.3), no thousands separators or fixed decimals; percent formats ×100 + "%"; date formats → `yyyy-MM-dd`, date-time → `yyyy-MM-dd HH:mm`, time → `HH:mm`/`HH:mm:ss`, honouring date1904 and Excel's fictional 1900-02-29. Formula cells show their cached value; files saved by tools that don't cache results (e.g. openpyxl) show those cells empty.
- M11: `FEATURE_PROCESS_DOCDECL` is set to false where the parser allows it; kxml2 (JVM tests) rejects setting it, and it is off by default everywhere. Added `net.sf.kxml:kxml2` as a test-only dependency.
- M11: CSV/TSV are read as bytes (max 50 MB, cut at the last line break) and decoded with `TextCodec`; TSV by extension/MIME, other files by delimiter detection over the first 5 lines (`,` `;` tab `|`). CSV/TSV ≤ 5 MB show the Edit pill (text editor), same encoding rules as text.
- M11: The grid draws each row in one pass with a `TextMeasurer` (no composable per cell) and reads the shared horizontal offset only while drawing; only on-screen columns are drawn. Tapping uses one gesture handler per row; each row has one TalkBack description ("Row 5: a, b, c"). Search outlines the current cell and scrolls it into view; Sheets have no Paper option or Print.
- M11: Emulator frame timing can't judge grid smoothness: every viewer (PDF, Word, grid) measured 57–73 ms median frames on the API 37 emulator's debug build. Re-check on a release build / real phone in M14. The 50k-row CSV opens in ~2 s and used ~132 MB PSS.
- M11: Samples in sample-files/sheets (3-sheet XLSX with dates, times, percent, shared strings, a 60-column sheet; truncated damaged.xlsx; 50,000-row CSV; semicolon CSV) come from an openpyxl script in `D:\Android\pyenv`.
- M12: `PptxReader` builds a small XML tree per part (`core/files/Xml.kt`, capped at 50 MB, no DOCTYPE processing) instead of streaming: slide parts are small and placeholder/style inheritance needs random access. `LimitedStream` moved to `core/files` and is shared with the XLSX reader; `RandomAccess.file()` (copy to `cacheDir/open/`) is shared by XLSX and PPTX; the "Simplified …" note moved to `core/viewer/SimplifiedNote.kt` (Word and slides).
- M12: Beyond the plan's minimum, text inherits through list styles (shape → layout placeholder → master placeholder → master title/body/other text styles) for size, bold/italic/underline, colour, alignment and bullets; `normAutofit fontScale` shrinks text; theme colours (`schemeClr` via the master's colour map) and the background chain slide → layout → master are honoured. Colour modifiers (lumMod/tint), gradients, picture fills, rotation, flips, crops and custom geometry are ignored; ellipse/roundRect shapes get rounded clips. Groups apply their child transform at every depth (the plan allowed flattening below one level). `mc:AlternateContent` uses the fallback.
- M12: Symbol-font bullets (Wingdings "§", "Ø", ...) become "•" unless the character is a real bullet glyph; auto-numbered paragraphs count per level.
- M12: Slides show in a `HorizontalPager`, fitted inside the page (width- or height-limited), text sized from points with the system font scale ignored (like a picture of the slide). Tables, charts and diagrams are labelled boxes; table text appears in the box (scaled with the slide), the outline and search. No pinch zoom on slides in v1.0.
- M12: "Outline view" is a More-sheet toggle: every slide's title, bullets, table text and up to 4 picture thumbnails; tapping a slide opens it. Switching views keeps the current slide. Search counts every occurrence, jumps to its slide and outlines the shape.
- M12: Samples in sample-files/slides (20-slide 4:3 deck from python-pptx's default template with bullets and sub-levels, the 50 MP photo, a table, a chart, a group, a dark slide; truncated damaged.pptx). Memory with the 50 MP picture on screen: ~119 MB PSS (Coil decodes at display size).
- M13: Archives are read with `ZipFile` over a random-access copy (`RandomAccess.file`), not `ZipInputStream` as planned: the central directory gives the full listing instantly (a 1 GB bomb lists in no time) and single entries extract without inflating everything before them. Names are UTF-8, retrying the DOS code page (IBM437) when that fails. `__MACOSX/` and `.DS_Store` are hidden; listing stops at 10,000 entries.
- M13: Android 14+ (`ZipPathValidator`) rejects a whole archive when any entry name has ".." or a leading "/". `FolioApp` clears that callback on API 34+; Folio lists such entries under their raw name at the top level and refuses to open them ("its path points outside the archive"), extracting only through `ZipSafety.safeTarget` + `Budget`. Verified: nothing is written outside `cacheDir/archive/<sha1(uri)>/`.
- M13: `java.util.zip` refuses any archive containing an encrypted entry ("invalid CEN header (encrypted entry)"), so password ZIPs show "Password-protected ZIPs are coming soon." for the whole archive. `encryptedNames()` reads the flag from the central directory as a second guard for runtimes that do open them.
- M13: A compression bomb is stopped by `ZipSafety.Budget` after ~50 MB at >100:1, the partial `.part` file is deleted, and the user sees "This item is too large to open safely."
- M13: Entries open through a new `ViewerActions.openFile(uri, source)` as `file://` URIs (read-only, Save copy for edits), with `record = false` (not in Recents) and source `archive:<name>`, shown as "From <archive name>". Back inside an archive goes up a folder first (`BackHandler`); breadcrumbs are tappable. ZIP's empty date (1980-01-01) is hidden.
- M13: `CacheCleaner` runs on a low-priority thread at app start and deletes files in `cacheDir/archive` and `cacheDir/open` older than 24 h (plus emptied folders).
- M13: Samples in sample-files/archives (nested project-files.zip with a PDF, DOCX, CSV and Markdown; zip-slip.zip with "../../" and "/abs/" entries; zip-bomb.zip with 1 GiB of zeros; password.zip with the encryption flag set) come from a Python zipfile script.
